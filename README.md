# sl-oj-lib-logging
Document updated 2026-11-01
Objo version: 26.10.5

## Library of Objo components to handle log messages.

This repository contains the library, under 'Shared' and a test project under Projects.

To test the library, simply download the repository and open the solution. If you like what you see, you can transfer the library to your application by copy/pasting the folder sl-lib-logging using the IDE.

## The library

### The main class: clLogManager

This class provides all the services needed to handle messages generated by the application. The shared method GetDefaultLogingSupport() returns a default, common instance of clLogManager. The instance of clLogManager is allocated on first call and reused for each subsequent call. 

The logManager provides a single logWriter sending the message to the output, using Print, or ErrorPrint dependning of their severity.

```objo
    var log as lib_LogManager.clLogManager
    ...
    
    log = lib_LogManager.clLogMAnager.GetDefaultLogingSupport()
    
```

The instance is silently destroyed by a call to ResetDefault(). This is not really required, unless you want to use the clLogManager is a specific part of the application.


```objo
lib_LogManager.clLogMAnager.ResetDefault()

```

### logWriter and the itfLogWriter interface

#### The itfLogWriter interface
The library uses classes called logWriter, implementing the itfLogWriter interface. 

A custom listbox child class implementing the itfLogWriter interface

The example program constains a class name ListBoxLogWriter. 

The Opening event handler of this class contains the following code to configure the listbox:

```objo
Self.ColumnCount = 4

Self.HasHeaders = True

Self.SetHeaderText(0) = kSeverity
Self.SetHeaderText(1) = kWhen
Self.SetHeaderText(2) = kWho
Self.SetHeaderText(3) = kMessage

RaiseEvent Opening()

```
It implements the method AddLogEntry(), the only method required by the itfLogWriter interface, as follow:

```objo
Var row As Integer = Self.AddRow()

Self.SetCellText(row, 0) = MessageSeverity
Self.SetCellText(row, 1) = MessageTime
Self.SetCellText(row, 2) = MessageSource
Self.SetCellText(row, 3) = MessageText

Self.ScrollToRow(row)

Return
```

'Standard' logWriters
The library provides two logWriters:
- clDebugLogWriter(): to send messages to the output 
- clTextFileLogWriter(): to send messages to a text file


#### Adding a log writer to the logManager

This code, used in the opening event of the window from the demo project:

```objo

Self.log = lib_LogManager.clLogManager.GetDefaultLogingSupport()

Self.log.UpdateWarningMessageHandling(10, True)

Self.log.AddWriter("LB01", LogListbox1)
Self.log.AddWriter("LB02", LogListbox2)

Return

```
The first line obtains the default logManager.

The second line is related to the handling of warning message, more about that later.

The third and fourth line add the two Listbox logWriter.

#### Disabling the default logWriter

The ID default logWriter is cstInternalWriterId. It can be disabled as follow:

```
log.DisableWriter(cstInternalWriterId)
```

A disabled logWriter does not receive any messages. But it is still registered with the logManager and can be enabled at any moment. For example:

```
log.EnableWriter(cstInternalWriterId)
```



### Writing messages

#### Writing a simple message

```objo
log.WriteMessage("TestButton1", "This is an information message")
```

#### Writing a message with template and parameters

```objo
log.WriteMessage("TestButton1", "Customer %0 has no name",CustomerID)
```
or better

```objo
log.WriteMessage("TestButton1", MsgCustomerNoName ,CustomerID)
```
with constant MsgCustomerNoName defined as "Customer %0 has no name".


### Warning messages

#### About Warning message
The logManager maintain a counter of calls to WriteWarning() When the counter reaches a predefined limit, a last message is shared with the logWriters and following calls to WriteWarning() have no effect. 

The counter is reset by a the following call

```objo
log.ResetWarningCounter()
```

#### About Warning message with ID
Calls to WriteWarningWithID maintain a distinct warning counter per ID. The ID is a user defined string. It is only used to identify the warning counter. It is not part of the message sent to the logWriters. For example, if a given condition generates many warning messages, one can call WriteWarningWithID() a use a distinct ID for this condition. The manager will automatically silent those warnings without affecting other warning messages.

The counter is for warnings "ALPHA" reset by a the following call

```objo
log.ResetWarningCounterForID("ALPHA")
```

All warning counters are reset by the following call


```objo
log.ResetAllWarningCounters()
```

#### Updating the limit for warning messages

The maximum number of warning message can be updated by calling

```objo
UpdateWarningMessageHandling(limit, InformOnReset)
```
The new limit is defined by the first parameter. The second parameter enables or disables the generation of a message when the counter is reset.


### Error messages

#### About error messagess

The logManager maintain a counter for error messages. When the number of call to WriteError() reaches that limit, the logManager will no longer forward the messaages to the logWriters. The logManager can be configured to generate a fatal error message when the limit is reached. A fatal error message is shared with the logWriters and the logManager tries to stop the application by calling system.Quit()


#### Updating the limit for warning messages

The maximum number of warning message can be updated by calling

```objo
UpdateErrorMessageHandling(limit, limitIsFatal, informOnreset)
```

The new limit is defined by the first parameter. 
The second parameter enables or disables the generation of a fatal error message when the limit is reached.
The third parameter enables or disables the generation of a message when the counter is reset.

### Message severity

Message severity

| Severity   | Method | Constant |
|---------------|--------------------|---|
| Information   | WriteInformation() | cstSeverityInformation |
| Message       | WriteMessage()     | cstSeverityMessage |
| Warning       | WriteWarning()     | cstSeverityWarning |
| Warning       | WriteWarningWithID()     | cstSeverityWarning|
| Error         | WriteError()       |  cstSeverityError|
| FatalError    | WriteFatalError    |  cstSeverityFatal|
| Debug message | WriteDebugMessage  |  cstSeverityDebug|

#### Filtering message severity
The logManager handles a global severity filter and a severity filter associated with each writer. 

The global severity filter is updated by a call to 

```objo
UpdateSeverityFilter(SeverityLevel, AllowOutput)
```

Where the severitylevel is the constant in the table above and the AllowOutput boolean is used to enable (when true) or disable (when false) the transfer of messages with given severity to the logWriters()

The individual severity filter is updated by a call to 
```objo
UpdateWriterSeverityFilter(WriterId, SeverityLevel, AllowOutput)
```
Example taken from the test project:

```objo
#
# From the opening event
#
Self.log.AddWriter("LB01", LogListbox1)
...
#
# From the event handler of the checkbox 'Accept Warning'
#
log.UpdateWriterSeverityFilter("LB01", lib_LogManager.cstSeverityWarning, Me.Checked)

```

## Tracing execution
The logManager allows to trace method calls and the execution of tasks.

The main difference between a method and a task is related to the fact that the logManager does not keep history of tasks: when a task is completed, information about the task are shared in a message sent to the logWriters and deleted; when a method is exited, the logManager preserves the information and information are cleared upon request.

Additional message severity are defined:

| Severity   | Method | Constant |
|---------------|--------------------|---|
| Summary   | WriteSummary | cstSeveritySummary |
| Statistics   | WriteStatistics | cstSeverityStatistics | 



### Tracing method calls
The methods EnterMethod() and ExitMethod() can be called to register to number of calls and the time spent in the method. The results are sent to the logWriters by a call to WriteAllMethodStatistics()
The results can be cleared by a call to ClearAllMethods()

| Method   | Purpose |
|---------------|---------------|
| EnterMethod()   | Register the start of a method |
| ExitMethod()   | Register the end of a method |
| WriteMethodStatistics()   | Write statistics about one method |
| WriteAllMethodStatistics()   | Write statistics about all methods |
| ClearAllMethods()   | Clear all statistics |



### Execution of tasks
The logManager() is informed that a task is started by a call to StartTask(taskname) and to EndTask(taskname) when a task is completed. The call to EndTask() causes logManager to share an information message with the name of the task and its total execution time. Multiple tasks can be registered independantly.

| Method   | Purpose |
|---------------|---------------|
| StartTask()   | Register the start of a task |
| EndTask()   | Register the end of a task |

Example

```objo
log.StartTask("MAJOR")

...

log.StartTask("Minor1")

...

log.EndTask("Minor1")

...

log.StartTask("Minor2")

...

log.EndTask("Minor2")

...

log.EndTask("MAJOR")
```

All tasks can be marked as ended by a call to EndAllTasks()
